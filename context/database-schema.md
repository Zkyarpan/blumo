# Blumo — Database Schema

## General Rules

- Use PostgreSQL UUID primary keys generated by the database.
- Use `timestamptz` for all timestamps.
- Store user-facing local timezone as an IANA timezone string.
- Add `created_at` and `updated_at` where records may change.
- Enable Row Level Security on every user-owned table.
- Use foreign keys with explicit delete behaviour.
- Never expose service-role access to the browser.
- Prefer database constraints over application-only assumptions.

## Tables

### `profiles`

Extends the Supabase Auth user.

| Column | Type | Notes |
|---|---|---|
| `id` | uuid | Primary key; equals `auth.users.id` |
| `github_user_id` | bigint | GitHub's stable numeric user ID |
| `github_username` | text | Current GitHub login |
| `display_name` | text | Nullable |
| `avatar_url` | text | Nullable |
| `timezone` | text | Default `Europe/London` only when selected or detected with consent |
| `experience_level` | text | `beginner`, `intermediate`, or `advanced` |
| `onboarding_completed_at` | timestamptz | Nullable |

| `updated_at` | timestamptz | Default now |

Constraints:

- `github_user_id` unique when present.
- `github_username` stored in normalized form for lookups.
- `experience_level` checked against allowed values.

## Row Level Security Model

### User-Owned Reads

A signed-in user may select rows only when:

```sql
user_id = auth.uid()
```

For `profiles`:

```sql
id = auth.uid()
```

### User-Owned Writes

A signed-in user may insert or update rows only when the target `user_id` equals `auth.uid()`.

### Sensitive Server-Only Operations

The following happen only through trusted server boundaries:

- Upserting verified GitHub installation metadata.
- Synchronizing repository access from GitHub.
- Creating commit records after a GitHub response.
- Writing audit events for webhooks.
- Recording system-generated scheduled tasks.
- Processing uninstallation or suspension webhooks.

Service-role access is used only in server-only code after independent authentication or webhook verification.

## Delete Behaviour

- Deleting an Auth user should cascade or invoke a controlled cleanup of user-owned application data.
- Uninstalling the GitHub App does not delete task history; it marks installation and repository access inactive.
- Removing a repository marks access unavailable but preserves historical commit references.
- Deleting a goal archives associated task history rather than silently deleting completed work.

## Indexes

Add indexes for:

- `goals(user_id, status)`
- `github_installations(user_id, status)`
- `repositories(user_id, is_selected, access_status)`
- `daily_tasks(user_id, created_at desc)`

- `commits(user_id, created_at desc)`
- `schedules(is_active, next_run_at)`
- `audit_logs(user_id, created_at desc)`
